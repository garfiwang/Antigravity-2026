# 🎟️ 活動線上報名與現場掃碼簽到全自動系統 (`event-registration-system`)

> **版本**：`v1.0.0`  
> **適用類型**：Google Antigravity / AI Coding Assistant / Google Apps Script (GAS) 自動化  
> **核心職責**：零成本、極速打造「線上報名 + 現場掃碼簽到 + 後台試算表雙重連動 + 自動發送即時確認與行前提醒 Email + 雙短網址與高解析 QR Code」全流程自動化系統。

---

## 📖 技能簡介 (Overview)

在籌備各類實體線下講座、桌遊推演、商業分享會、工作坊或線上研討會時，主辦方常面臨以下困擾：
- 市面報名工具（Accupass、SurveyCake、Google 表單）常需收費、無法客製發信邏輯或版面受限。
- 報名後需手動導出名單寄送確認信，活動前一天還得加班手動發送行前提醒。
- 活動現場報到混亂，使用紙本簽到難以即時統計，甚至有人現場臨時前來無法與原報名名冊整合。
- 一般民眾常因遇到「需要登入 Google 帳號」或「多帳號切換錯誤」而放棄填表。

**`event-registration-system` 技能徹底解決了以上痛點！**  
只要在對話中輸入 **「製作報名表單」** 或 **「製作報名連結」**，AI Agent 將全自動完成前台網頁刻畫、後端試算表建置、發信排程、現場簽到路由、短網址產生與高解析 QR Code 輸出，全程只需 2~3 分鐘！

## 🏗️ 系統架構與資料流 (Architecture)

```text
[ 一般民眾 ] ──( 掃描報名 QR / 點擊短網址 )──> [ 線上預約報名表 index.html ]
                                                      │
                                                      ├──> [ Google 試算表 gid=0 ] (寫入報名紀錄)
                                                      ├──> [ 即時寄送確認信 Email ] (MailApp)
                                                      └──> [ 自動註冊行前通知排程 ] (活動前一天 18:00)
                                                                    │
[ 現場來賓 ] ──( 掃描現場簽到 QR Code )──────> [ 現場簽到表 checkin.html ]
                                                      │
                                                      ├──> 智慧比對 gid=0 (標記簽到時間 + 變綠色)
                                                      └──> 寫入「現場簽到紀錄」分頁 (依序號流水列出)
```

## 🕳️ 實戰踩坑記錄與避坑指南 (Troubleshooting & Pitfalls)

在真實部署 Google Apps Script 過程中，團隊踩平了許多官方沒明說的「暗坑」，特此完整記錄：

### 坑 1：Web App 權限設定錯誤引發 Google 登入牆與多帳號切換錯誤
* **現象**：一般民眾點擊短網址時，出現「`很抱歉，目前無法開啟這個檔案。請檢查網址並再試一次。`」，或是強制跳轉至 Google 帳號登入畫面（網址帶有 `/u/2/`、`/ServiceLogin`）。
* **原因**：`appsscript.json` 中 `access` 若設為 `"ANYONE"`，Google 會要求訪客「必須登入 Google 帳號」；一旦訪客未登入或同時登入多個帳號，就會觸發 Google 帳號授權限制與重導向 bug。
* **解法**：必須在 `appsscript.json` 明確設定為：
  ```json
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
  ```
  讓後端腳本以擁有者身分背景執行寫入試算表與寄信，對外大眾完全免登入、免授權！

### 坑 2：clasp 建立部署與初次部署授權機制
* **現象**：全新建立的 Apps Script 專案在透過 CLI 部署後，未登入的 curl 或訪客可能得到 HTTP 403 / `需要存取權`。
* **原因**：Google 要求專案擁有者必須先授權一次 OAuth 範圍（發信、讀寫試算表）。
* **解法**：主辦人首次在瀏覽器開啟 Web App 或 Apps Script 編輯器，點擊「審查權限」→「進階」→「前往（不安全）」→「允許」，完成這一次授權後，所有外部民眾即可永久免授權匿名存取！

### 坑 3：Web App 網址不可自己手拼（scriptId vs deploymentId）
* **現象**：自己組裝 `https://script.google.com/macros/s/<scriptId>/exec` 永遠回傳 404 或網頁不存在。
* **原因**：`scriptId`、`parentId`、`deploymentId` 是三個完全不同的 ID。網頁應用程式必須是 deploymentId 經由 API 產出的 `webApp.url`。
* **解法**：一律使用 `npx @google/clasp open-web-app <deploymentId> --json` 取得官方 API 回傳的正確網址。

### 坑 4：單一專案實現雙介面（報名 + 現場簽到）
* **現象**：傳統若要做報名又要做現場簽到，往往建兩個 GAS 專案，導致試算表授權繁瑣、維護混亂。
* **解法**：透過 `doGet(e)` 判斷 `e.parameter.page === 'checkin'` 路由，單一專案同享憑證與後台試算表，再分別透過 Reurl 產出獨立短網址，大幅降低維護成本。

### 坑 5：行前提醒自動排程觸發器未啟動
* **現象**：如果忘記在 GAS 介面手動建 trigger，活動前一天不會自動發行前信。
* **解法**：在 `submitRegistration()` 裡加入 `ensureReminderTrigger()`，只要有人報名（或主辦人測試填寫），程式在背景自動檢查並向 ScriptApp 註冊活動前一天的定時觸發器，達到真正的「零人工干預」全自動化。

### 坑 6：現場重複簽到與同行友人代簽
* **現象**：現場民眾常有一人幫同行親友簽到，或重複按鈕。
* **解法**：簽到成功頁面設計「➕ 替同行友人簽到」一鍵重設按鈕；後台主表使用姓名比對更新第 10 欄，獨立簽到分頁則依序記錄，避免覆蓋又具備時間順序流水號。
